# The S3 firmware's stack frames and call graph, checked in CI against the X4 Classic
# (ESP32-S3, `ppn5`) build: `paperpaw-sign frames-s3 <elf> --budget shells/xteink/frame-budget-s3-classic.txt`.
#
# The roots are the function pointers of the host table (`PAPERPAW_HOST_TABLE_ANCHOR`,
# shells/xteink/src/native/ppn5.rs): every host entry a plugin can call. The scan follows
# each direct call and each `l32r` + `callx8` call whose literal is the same on every path,
# holds every function reached to a frame under 2,048 bytes (the stack band's bound,
# `abi/heap-word.md` section 6), and refuses `call0`/`call4`, any write to `a1` and any
# instruction form it does not classify. What it cannot see is listed below, one line
# for each, with the reason; a line that matches nothing fails, and so does a site that is
# not listed. The device's overflow test (S4) covers what static reading cannot: the depth of
# a path of calls, and the callees behind the indirect calls.
#
# The X4 Pro and the X4 Classic are two builds of the same code with different symbols (hashes,
# a few instances) and so two budgets: frame-budget-s3.txt and frame-budget-s3-classic.txt.
#
# The ELF is built with legacy symbol mangling so that the names below are plain paths:
#   cargo +esp build --release --target xtensa-esp32s3-none-elf --no-default-features \
#     --features x4-pro,ppn5 -Zbuild-std=core,alloc \
#     --config 'target.xtensa-esp32s3-none-elf.rustflags=["-Z","unstable-options","-C","symbol-mangling-version=legacy"]'
# A function is named by its path; the path drops the generics, so when other functions of the
# image share it (every `drop_in_place<..>`, each instance of a generic) the scan names it by
# its symbol without the compiler's hash and without LLVM's `.NNNN` suffix (both change from one
# build to the next, an unrelated change included, so a line that kept them would fail every other
# pull request). That name is the same for each instance of one generic function: a line naming it
# covers the instances whose site it describes (`allow indirect` by its count, `allow call` by its
# callee); an instance with another count needs its own line. A line whose path matches more than
# one function reached is an error. A line changes only when the code behind it does.
# Roots: besides the host table, the impls behind the trait objects the host's paths call through
# (`root trait`: every impl method and default method of a trait; `root impl`: one type's). Not
# rooted, and why: `&dyn Frame` (`abi7::context::Frame`) has no impl in this image (the dispatch
# frames, `Env` and `CoreFrame`, are not instantiated until the linked-plugin path of todo 150 is
# wired: add `root trait paperpaw_core::abi7::context::Frame` with it; the root fails while it
# matches nothing, so it cannot be forgotten); the registration sink (`Target<T>` of
# registration_scope.rs) has no symbol of its own for its methods (generic over the make closure,
# merged into the registration closures), so its calls are listed here and left to device test S4.
#
# Regenerate this file from CI's ELF: build in CI's checkout path (`/home/runner/work/paperpaw/paperpaw`,
# CI's command, as above) and scan it. The same commit built in another directory can differ by a
# line or two (LLVM's inlining depends on the build's layout); the CI path is the one that counts.
# To refresh the lines after a change: run the scan, read what it reports, and decide for
# each site (a new indirect call needs its reason, not a number changed).
