### Changed

- `paperpaw-sign frames-s3` follows a `callx8`/`callx12` whose register an `l32r` loaded (the S3's long call: 71,308 of the 78,606 calls in an X4 Pro image) as the direct call to the literal's address, so the scan reaches the code behind the host entries instead of stopping at the first call. The analysis is a forward pass over the function (an `l32r` makes its register hold its literal; a write, a call from its rotation up, `entry` or a window register takes it back; paths that disagree lose it) and fails closed, leaving the calls indirect and listed, at a branch form it does not model, a branch into the middle of an instruction, a hardware loop or a call the flow never reaches. Literals are read from sections the program cannot write. A `rotw` is judged as a change of the stack pointer (`allow sp`) instead of an unclassified form. One problem line per caller and callee, not per call site.
