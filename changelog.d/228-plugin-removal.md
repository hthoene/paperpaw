### Added
- The removal of an installed plugin (`remove_plugin`, `docs/abi/device.md` 5.2, 5.4; decision 124) as a job of the host: `core` and the plugins built into the image are refused (reason 15), one question with three answers (remove and keep the data, remove with the data, cancel; the trusted-installer grant never skips it), then a journalled removal (`plugins/.journal`, record kind 1) that closes the plugin's instances first, moves `plugins/<id>` and, if chosen, `.paperpaw/plugins/<id>` into `.removing-<id>` folders by the card's journalled move (the ids are checked names compared whole, never a path a plugin gave: removing `battery` leaves `battery-plus`) and removes them there. A cut at any point is finished by the same steps at the next start: the plugin is whole, or removed with its data only if chosen. Pins stay, so a reinstall still comes from the pinned author.
- At start, before plugins are found, a plugin install or removal a cut left is finished, and a journal that can never be finished (a state no step makes) or cannot be read is set aside as `plugins/.journal.bad` with a line in the log instead of blocking every later install with reason 1. Leftover stages `.<id>.part`, `.removing-<id>` folders and a half-written journal are swept, at most eight a start; an `.old-<id>` folder never is, since it can be the only copy.
