# PaperPaw 0.6.0-beta.4

Beta 4 is the first PaperPaw whose built-in plugins are all interface-7
plugins, and the first whose images may not fit the small CrossPoint layout. Read "Before you update"
first; the rest is what is new, better, fixed and changed since Beta 3.

Items marked **[confirm]** have to be checked on a real device (the release tests)
and the mark is taken away when they have been.

## Before you update

- **Beta 3 updates to Beta 4 over Wi-Fi** (Decision 272). On Beta 3, open
  Update and search online: it offers PaperPaw 0.6.0-beta.4, downloads it and
  installs it as any update. Books, settings and reading places on the card are
  kept. Beta 3's update page may list built-in plugins that are not separate
  plugins in Beta 4 any more (the old hyphenation and Wikipedia plugins; the
  features are in Beta 4 in their new form, English hyphenation is put back at
  the first start) and offers to download without them. Plugins with code
  that were built for interface 6 stay on the card; Beta 4 does not load them
  and says so (see below). Beta 1 and 2 are offered the same file, but only
  Beta 3 has been checked. A device that keeps
  the small CrossPoint layout (slots of 6.25 MB) cannot take the image: its
  installer refuses it before it writes anything and the device keeps
  running; flash PaperPaw once with the web flasher at paperpaw.org/flash,
  updates work on the device from then on. Beta 4's own update page says this
  before it downloads anything. Checked on an X4 with Beta 3 and the update file on the
  card (books, settings and reading places kept); the online way from Beta 3
  (*Search online*) is **[confirm]**.
- **Going back to Beta 3 is possible:** see "Going back to Beta 3" below.
  Nothing is lost, but a few things are not shown.
- **Interface 7: plugins built for interface 6 no longer load.** Beta 4 is
  interface 7. A plugin with code that was built for an older interface is not
  loaded any more and has to be rebuilt by its author (plugins without code,
  such as dictionaries, fonts, hyphenation and themes, are not affected).
  Plugins in the store are rebuilt. Plugin authors: use `paperpaw-dev new
  --code` for a new plugin; the old Rust plugin API, the old screen API and the
  old plugin-file formats are gone.
- **Hyphenation is no longer built in.** English is put on the card at the
  first start that finds none. Other languages are optional packs in the
  store; German is `hyphenation-de`. If you read German books with hyphenation
  on, install it from the store after updating (Beta 3 had German built in).
  A book in a language whose pack is missing (German and eleven more) asks the
  store for it when you open it with *Hyphenate words* on, once for each book;
  nothing is downloaded unless you say *Download*.
- **Literata is a store pack.** The firmware no longer carries Literata (257 KB
  less flash). If you had chosen it, your choice is kept and Home shows a
  one-time notice with a shortcut to the store once Wi-Fi is set up.

## Devices

Beta 4 supports all four Xteink readers: the **X4**, the **X4 Classic**, the
**X4 Pro** and the **X3**. Each has its own image in the release; the X4 and
X3 run the built-in plugins natively, the X4 Pro and X4 Classic host them like
the X4. The **Boox Picco** is experimental (see "New"). The **Android app is
not promoted** in this release: it is not part of the supported devices and
has no announcement or download page.

The **X3** works in Beta 4 including the newer panel: X3s made from about
July 2026 have a UC8279d display controller that Beta 3 drove wrongly (#408), and
the store and other secure connections work on the X3 again (#410). Measured on an X3
with a Beta 4 image of Nov 20: start 5.4 to 6.0 s, a page turn 0.82 to 0.88 s, a
full refresh 1.13 to 1.26 s; on Home with Wi-Fi off 114 KB of the heap are in use
and 148 KB are free.

The **X4 Pro** and the **X4 Classic** host the built-in plugins on the ESP32-S3
(measured on test builds of Nov 20 with the flash read at 80 MHz, one device each).
X4 Pro: start 3.43 s (3.38 to 3.52 s), a page turn 0.85 s, a full refresh 1.87 s, a
book (Alice) open in at most 6.8 s including about 2 s to set up the link, 157 KB of
the heap in use on Home; the store list (23 KB) loads in 1.97 s and an online
look-up works. X4 Classic: start 3.35 s (3.31 to 3.37 s), a focus step on Home 0.75
to 0.82 s, a page turn 1.7 s, Alice opens in 3.1 s, a picture EPUB in 7.3 s, a 5 MB
text file in 4.3 s, 148.6 KB of the heap in use on Home; the store list loads in
2.6 s and an online look-up works. The X3 and the Picco keep their flash at 40 MHz.

## Plugins copied to the card

- **Code plugins copied to the card run without a question.** A plugin folder
  you copy onto the card runs its code at the next start, unsigned. Only copy
  plugins you trust. Checked on the X4.
- **Plugins from the store stay signed** and run only the file that was
  installed.
- **Settings > Manage plugins marks plugins that were not installed.** Their
  note says the code was copied to the card, runs unchecked, and points to the
  store. Checked on the X4.
- A plugin that was once installed signed never runs from a copied folder, and
  a copied plugin that wants to install plugins or firmware is not run: those
  still need a real install. If the list of installed plugins cannot be read,
  no copied code plugin is loaded.
- A folder left on the card by Beta 3 never stands in for a plugin that is
  built in now.

## Going back to Beta 3

You can flash Beta 3 (or Beta 1 or 2) onto a device that has run Beta 4.
Nothing is lost: books, settings, reading places, last book and every file on
the card stay as they are, and all of it is back when you update to Beta 4
again. Checked on the computer with the code of each version and on an X4 with
Beta 1, 2 and 3. What the older version does not show:

- **Highlights and bookmarks** in a book that Beta 4 changed (its notes file is
  a newer version) are not shown, and the older version cannot add to them. The
  file is kept.
- **Plugins built for interface 7 are not listed.** A warning names them; their
  folders stay on the card.
- **Passwords saved by Beta 4 must be entered again**: the Wi-Fi network is
  listed, but its password (and those of mail and other accounts) is sealed by
  Beta 4 and the older version cannot read it.

## New

- **All built-in plugins are interface-7 plugins:** Home, the reader, Settings,
  the menu, the plugin manager and store, Library, Update, Transfer, Wi-Fi,
  Bluetooth, Mail, Dictionary, Vocabulary, Widgets, Sleep, Lock, About and the
  rest. The X4 and X3 run them natively, and the X4 Pro and X4 Classic host
  them like the X4 (checked on the X4, the X4 Pro and the X4 Classic).
- **The Boox Picco, experimental** (#368): a firmware for Onyx's Boox Picco comes
  with the release (`paperpaw-picco-<version>-install.bin`), flashed over USB
  into the stock firmware's app partition; Onyx's boot loader and recovery stay
  as they are. It is built from what others found out about the device and has
  **not been tried on a Picco**: it may show nothing or not start. Save the
  Picco's own flash first, it is the only way back to its stock firmware
  (`shells/xteink/README.md`). Touch, the front light, two page buttons, Wi-Fi
  and Bluetooth; no update from the device itself (one app partition). The
  emulator has it as the profile `boox-picco`.
- **Status bar on every screen** (Settings, Status lines, *Status bar on all
  screens*; off to begin with): the time and the battery in a thin bar at the
  top of every screen that has no status line of its own. Home and the page of
  a book keep their own. Advanced settings choose it per screen. Only the bar
  is refreshed when the time or the battery changes. **[confirm]**
- **Full refresh in menus:** an advanced Display setting counts the refreshes of
  the user interface and does a full one after the number you set. **[confirm]**
- **Mail can check in the background** (Mail settings, *Check for new mail in
  the background*; off to begin with; every 15, 30 or 60 minutes). It checks
  one account at a time while the reader is awake and online, and the Home
  widget shows the unread count. A mail's attachment in a book format (EPUB,
  PDF, MOBI, AZW3, FB2, TXT, DOCX, CBZ) opens as a book (*Open book*).
  **[confirm]**
- **Passwords in plugin settings are kept secret:** a plugin can mark a setting
  as secret (the mail password is one). It is stored with the encrypted
  passwords, never in `paperpaw.ini`, and can be entered, changed or cleared in
  Settings. A password an older card keeps in `paperpaw.ini` moves there at the
  start (on the X4 once Wi-Fi is on).
- **Choose your own screens for switching off, starting and restarting**
  (Sleep screen settings): *Show when switched off* (the sleep screen, the
  logo, the cat, the cover, your pictures or a screen of a plugin), *Show when
  starting* and *Show when restarting*. The off screen is also drawn when
  *Switch off after sleeping* passes on the X4 and X3. The start screen is
  prepared when the device switches off or restarts and shown at the next
  start; one that does not open in time gives way to the built-in screen. A screen
  of another plugin chosen as the sleep screen is now shown when the device
  sleeps (#354). **[confirm]**
- **A sleep screen that stays right while the device sleeps** (Sleep screen >
  *Redraw while asleep*, off to begin with): with the widgets (or a widget
  over the page) as the sleep screen, the clock, calendar and weather are
  drawn again every 15, 30 or 60 minutes at the next whole mark of the clock,
  with a partial refresh. The X4 and X3 wake from their light sleep for it and
  go back to sleep; nothing is loaded from the network (a weather or calendar
  widget shows what it already has), it stops with a battery at 10 % or less and
  once the device switches off after sleeping. Each redraw costs about 0.03
  mAh (an estimate, not yet measured): about 3 mAh a day every 15 minutes, 1.5
  every 30, 0.7 every hour, against 5 to 10 mAh a day asleep without it. The
  X4 Pro and X4 Classic keep the screen as it was. **[confirm]**
- **Edge light on the X4 Pro:** a swipe along the edge shows the light as the
  finger moves and saves it once, when the finger lifts, instead of writing the
  setting at each step. The level still moves in whole steps of 5 %. Checked on
  the X4 Pro (the plugin installed from a test store): a swipe up the left edge
  sets the brightness, with its notice, in steps of 5 %. That the light follows
  the finger while it moves **[confirm]**.
- **Links between notes** in a notes vault open the other note.
- **The library says when it cannot read its catalog** (a damaged file or a
  failing card) instead of showing no books.
- **A book no reading app reads is passed on** to the next app that does; with
  none left the reader closes with a notice.
- **Open with:** where two or more reading apps are installed, Settings >
  Reading chooses the default app and one for each format, and a book's menu
  in the library offers *Open with …*, *Always open with …* and *For this
  folder …*. With one reading app nothing shows.
- **Tap zones for reading** (Settings > Controls, on touch devices, the X4
  Pro; #381): choose where a tap turns the page or opens the menu: thirds with
  the menu in the middle (as before), halves with a menu strip at the top, an
  L-shape for one hand (the right and bottom edges go on), or top and bottom.
  *Swap left and right taps* mirrors any of them. Your own button and gesture
  changes still win. Checked on the X4 Pro: every choice, with and without the
  swap, turns or opens the menu where it says.
- **Memory cards: exFAT (experimental) and FAT16** (#54). The reader reads and
  writes exFAT cards (many cards of 64 GB and more are sold that way) with its
  own FAT driver, with the same safety as on FAT32: every change to a folder is
  one block's write, so a power cut leaves the files as they were or as they
  are now. Mounting a 64 GB card takes four card commands and about 14 KB of
  heap. The first time an exFAT card is used the reader says that exFAT is
  experimental and that FAT32 is the safest; FAT32 cards work as before. Older
  FAT12 and FAT16 cards mount on the device again. The exFAT code is written
  from hadris (MIT), see About PaperPaw. A new folder is cleared in one card
  command and a block read twice is not asked of the card again (the Library's
  first start and walk of 14 books: about a fifth fewer commands, counted in
  the emulator). **[confirm]**
- **Page layers: translations, glosses and read-along on the reader's page**
  (#284). Plugins can set text above, under and between the lines of a book
  (a translation under each sentence, small text over words, notes or a
  picture in a part of the page) and draw over the page. Page turns ask
  nothing they did not ask before; without such a plugin nothing changes.
  See "For plugin authors" for the new calls.
  - **The dictionary, Wikipedia and translation windows open next to the
    word** (#378): the window goes right below the word, or above it where
    there is no room below, and never covers it, instead of always rising from
    the bottom of the screen. *Online ›* in the dictionary opens Wikipedia in
    the same place. Where there is no place (a lookup from a list) the window
    is the sheet at the bottom as before.
  - **Translate in the reader's selection bar** (#378): the bar of chosen
    words has *Translate* after *Look up* where the translation plugin is
    installed and on.
  - **Gloss** (store plugin, #379): small text above the words of a book, for
    those who learn a language: how a word is read (furigana, pinyin, a
    pronunciation) or what it means in a word or two. The words come from a
    plain list on the card (`.paperpaw/plugins/gloss/<book>.txt` for one book
    or `<language>.txt`, such as `de.txt`, for every book in a language: a
    line each, the word, a tab, the small text). It is read once when the book
    opens; the size is set in Settings > Reading aids. Off until you switch it
    on.
  - **Read-along** (sample plugin, #377): marks the sentence being read aloud
    with a frame around its words on each line or a thick line under them
    (setting *Mark the sentence read aloud*). A mark word by word is not
    possible yet: the voice reports a sentence only at its end.
- **File sync and Syncthing:** the help of *File sync* now explains in four
  steps how to sync with a Syncthing folder through a WebDAV server on your
  computer or NAS (`rclone serve webdav`), in English and German (#380). The
  reader itself has no Syncthing.
- **Secure connections: a smaller firmware, 22 built-in root certificates and
  an optional full list** (X4 and X4 Classic; #387). The firmware keeps the
  root certificates of PaperPaw's own services, GitHub, the services of the
  plugins and the largest hosts (22 of them) instead of Mozilla's whole list,
  and TLS 1.3, the server side and a second cipher are left out (TLS 1.2 stays,
  which is what HTTPS servers use): against the build before them the X4
  firmware is about 104 KB smaller and the X4 Classic's about 85 KB (calculated from the
  parts left out, not measured on a before-and-after image; store list and download from paperpaw.org and a
  Gutenberg connection were checked on the X4; the Classic is not
  checked on a device). The full list is the new store plugin **All
  certificates** (off at first, signed by PaperPaw, read from the card only
  when a server's root is not built in). A server under another root fails with
  "Certificate not known. Install 'All certificates' from the store." Checked on the X4.
- **Pictures full screen, with zoom and pan:** hold Select on a page with a
  picture (touch: hold the picture) to see it alone. Left and Right step
  through the page's pictures, Select zooms to 2x and 3x (touch: double tap),
  Back goes back to fit and then to the page. Checked on the X4. With the new
  setting *Turn wide pictures* (Reading behaviour, off to begin with) a wide
  picture is turned a quarter there, so that it fills a tall screen. Checked on the X4.

- For plugin authors: **interface 7 grew by additions, nothing was taken away
  (#369): a plugin built for Beta 4 before them keeps running unchanged.**
  What a plugin can now use (see `docs/abi/` and `changelog.d`):
  - a status bar above a screen (`ScreenDecl::status_bar`, `ScreenPolicy::status_bar`; #123);
  - the picture stage `core.picture`: a plugin is asked once for each picture
    (of a book's page, a comic, a cover, the sleep screen or its own) and
    answers a tone curve, whether the picture is drawn in dots or grays
    (SDK `native::image::picture`; see `docs/abi/document.md` 5);
  - a part of a picture drawn without a copy on the card
    (`Canvas::draw_image_part`, host slot 44; a format names a part of a cache
    file with `fmt.image.part`) and a picture asked for turned a quarter
    (`PrepareImage::turned`, `Documents::ask_image_turned`);
  - a sleep screen asked to be shown again while the device sleeps
    (`CommandSender::show_again`, capability `RefreshAsleep`) and the input-filter
    verdict `preview`, which shows a setting's value without a card write until
    the capture ends (`FilterVerdict::new` now takes `key` and `value`, empty
    for the older verdicts: a plugin rebuilt from source passes them);
  - a reading app that cannot open a book passes it on to the next one
    (`CommandSender::pass_on`);
  - a download the user waits for asks for the larger buffers
    (`Request::foreground`);
  - `event.display_changed` tells the display's new size after a turn;
  - the snapshot says whether the row of hints shows (`Snapshot::hints_shown`);
  - a link can lead to another file on the card (`LinkKind::File`);
  - the library state can say the catalog could not be read
    (`CatalogPhase::Failed`).
- For plugin authors: **interface 7 draft 37 (#242), additions only: plugins
  built for draft 36 run unchanged.** A frozen service can gain ops (a plugin
  of an older or newer revision of a service loads; an op the host lacks is
  refused as unsupported: `Service::open_newest`, `Service::has_op`); a format
  can read only some books of its extensions and hand the others to the next
  format (`FormatDecl::asks`: a picture-book EPUB format beside the built-in
  one); a book can mix whole-page picture sections with reflowed ones
  (`FormatFeatures::some_whole_pages`); a download can ask never to take the
  larger buffers (`Request::priority`, `Priority::Lean`). A hook for one
  format to convert another's elements (MathML in EPUB) is not in Beta 4.
- For plugin authors: **page layers** (#284, #377, #378, #379): with
  `reader.text@1` a plugin sees each paragraph before it is laid out, may ask
  for room above and below its lines, replace words as shown, set glosses,
  ruby or phonetics and insert small blocks; with `reader.layer@1` it is shown
  each laid-out page once, with the places of its lines and words, and answers
  boxes, lines and text the reader draws over the page. A layer can follow
  reading aloud (`LayerAnswer::uses_reading_aloud`), keep the book's text to a
  part of the page (`LayerAnswer::region`) and draw a second text or a picture
  in the rest, take taps and keys before the reader acts on them
  (`LayerAnswer::input`) and draw again in one partial refresh. The lookup
  slots get the box of the looked-up words (`anchor`) so that a window can open
  next to the word. SDK: `native::page_layers`; samples: `samples/interlinear`,
  `samples/read-along`; see `docs/abi/page-layers.md`. Interface 7 is
  unchanged: plugins built before run as they did.
- For plugin authors: library queries can list only the books opened at least
  once (`Show::Opened`, #393); a host before it refuses the query with
  `Error::Invalid`. `paperpaw-dev build` makes the same plugin file from the
  same source in any folder, so the store can rebuild a community plugin and
  compare (#373); `paperpaw-dev check <file>.ppn` reads plugin files of
  interface 7. `paperpaw-emu --registry` lists the widgets that native plugins
  declare (#372).
- For plugin authors: the Linux emulator (`--trust-code`) installs code plugins
  from its store as real downloads, with its own catalogue name
  `emulator-linux-x86_64`, a signature checked and asked about like on a device
  (#278). The check that refuses a host library able to run code while it loads
  now also reads macOS (Mach-O) and Windows (PE) libraries (#233).
- For plugin authors: the kernel's own old plugin kit is gone (the rewrite of
  #300 is complete); plugins see no change on interface 7. A test script
  language (`tools/x4-remote.py --script-file`, also for the emulator) runs
  repeatable device tests.
- For plugin authors: `paperpaw-dev sweep` shows every screen of the app once
  in English and German and names screens that are cut, empty or untranslated;
  `reach` now says which screens the buttons cannot reach and which it could
  not decide; `visual`, `gallery` and `snapshots` look at all screens again;
  the plugin manager says why a plugin passes the limit of book fields, badges
  or lookup providers. A bad table-of-contents or link row of a format is
  dropped, not the whole page.
- For plugin authors: `paperpaw-dev` builds, packages and checks interface-7
  plugins with code for the X4, X3, X4 Pro, X4 Classic and the emulator; the
  SDK offers read aloud, reader marks, notices, nested clipping and many more
  calls. The emulator can take the card out and in (`card-out`, `card-in`).

## Better

- **Less memory on the X4:** the kernel keeps no event queues, no key maps and no
  screens that are not on show, a page of a book takes
  about 8 KiB less to draw, a frame about 11.6 KB less, and a Word document
  converts in less memory. Covers and conversions wait for a quiet second. Against Beta 3 the X4 still
  uses more heap (see "Known limits against Beta 3").
- **Faster:** pages turn with fewer card reads (hyphenation: 63 block reads
  per page turn instead of 328 in the emulator), a JPEG decodes with about half
  the computing, an EPUB's file list is read in pieces, large files written by
  appends take their clusters in runs, and Home asks the library once for each
  frame.
- **Home is quicker:** Back from a book to Home takes 0.87 s on the X4 (the
  first one after a start 1.43 s; measured on the X4 on Nov 20), also from a cover page, which no longer ends in a
  full flashing refresh. Covers show at once in black and white and their grays
  follow by themselves, and again after every rest of 30 s. Moving the focus
  draws only the two cells it leaves and comes to, without asking the library
  again, and tool names are no longer hyphenated.
- **Lists and pictures draw faster:** the store's lists and its setup pages
  are drawn with less work (a frame estimated at 1.9 s is estimated at 0.9 s on
  an X4, not measured on the device), every list in every plugin draws with
  less work, *All tools* about thirty times faster (counted in the emulator), and
  pictures (covers, the sleep screen's cat, reader pictures) are dithered and
  stored faster, pixel for pixel the same.
- **A focus move on Home reads no cover from the card:** what a cover drew is
  kept while Home is shown (3 KB a cover); on the X4, 9 of 10 focus moves read
  nothing from the card (measured). Words asked of the hyphenation again
  (names, lists drawn again) no longer read the language table from the card.
- **The sleep screen asks the card about 23 times** before its first frame,
  not 293 (counted in the emulator): a gray picture's brightness map is summed while it is decoded.
- **Fixed tables save heap:** Statistics, Battery and Notes overview, where
  built in, keep their settings in tables of the program, about 6 KiB less heap
  with all three on. No change for plugins loaded from files.
- **Start, opening a book and Back to Home write less to the card** (#389): a
  small file that already holds what is written is left alone. Counted in the
  emulator on a counting RAM disk: 30 to 6 write commands at a start, 25 to 6
  when a book opens, 14 to 2 on Back to Home; on the X4 each command costs
  about 5.6 ms. Not measured on the device yet. The start log now says where
  the time to the first frame goes.
- **Home reads less at its start** (#393): drawing Home read the plugins'
  declarations again for every row of a menu or widget list; they are read once
  for each question now, and Home's recent books ask the library only for the
  books opened before, not for a page of 32 books with a card read each.
- **The library gives its covers back while a book is open** (#344): the
  library list gives its covers back while a book is open over it and asks for
  them again when it shows.
- **Fewer card writes when you turn pages:** saving the reading place writes
  one block instead of a whole file (before: 13 to 25 block writes), and
  neighbouring changed blocks are written in one command. On the X4 a page
  turn writes 0.51 KB (one 512-byte block) and the new page is on the screen
  0.81 s after the key (0.75 to 0.84 s in 16 turns, measured on the X4 on Nov 20;
  Beta 3: 0.75 s; a turn with a full refresh takes 2.05 s). A key pressed while a picture is
  drawn in grays stops the gray pass at once (checked on the X4).
- **Less work at the start:** the X4, the X4 Pro and the X4 Classic read their flash at 80 MHz, and there is less card
  work at every start (the free space is not counted again, folders and
  plugin texts are read in pieces) and when waking from a light sleep. With the
  release image the X4 starts into the last book in 4.8 s (measured, see "Known limits
  against Beta 3"). **[confirm]** for the wake from a light sleep.
- **Smaller parts in the firmware:** about 90 KB less through folded code, a trimmed TLS
  (HTTPS keeps TLS 1.2) and records that are encoded from tables. The text wrapper of the screens is one
  body instead of 24 copies: 34.9 KB less on the X4, 38.2 KB on the X4 Classic
  (#388; measured on the built images, nothing changes on screen). The TLS
  roots and trim of #387 are counted in "New", not here.
  The firmware as a whole is still about 5 % larger than Beta 3's (see "Known limits
  against Beta 3").
- **About 254 KB less flash for the built-in font and icons**, 58 KB less for
  icon names, and the firmware carries only the translations of plugins built
  into it.
- **Faster plugin and language-pack downloads over Wi-Fi** (not measured):
  the radio stays out of power saving for two seconds after a request, files
  of one server reuse a connection, large downloads use bigger buffers where
  memory allows.
- **A packed update installs on the X4 with Wi-Fi on:** where the unpacking
  finds no memory, the device parks idle plugins, switches Wi-Fi off (the file
  is downloaded) and tries once more. Wi-Fi stays off afterwards. If there is
  still no room, the update says so and asks you to restart. Checked on the X4
  (the update in the app).
- **Large pictures in books use less memory:** a large PNG or long JPEG in a
  book (a 1600 x 1000 picture) is decoded from a file one step at a time and
  shrunk with less memory; its page peaks at about 214 KiB instead of 260 KiB
  on the X4 (counted in the emulator).
- **A store download no longer takes the last of the memory on the X4:** the
  secure connection is opened only with enough memory. Where there is not, the
  download ends and the store says "not enough memory, restart the device and
  try again" instead of staying blank.
- **Settings > Manage plugins no longer stops the X4 with the watchdog when
  Wi-Fi is on:** the list is drawn in far fewer steps. Checked on the X4.
- **Switching a plugin on or off in Manage plugins no longer freezes the X4**
  (#375): Settings built its main page once for every plugin switched (about
  16 seconds); it now builds a page only when it is shown (a switch takes 1 to 1.5 s on the X4,
  most of it the screen's refresh). Checked on the X4.
- **The update check on the X4 no longer fails at once with "the request
  failed"** (#395): it asked for an answer of up to 40 KiB, more than the X4
  allows (16 KiB), so the request was refused before it was sent. A failed
  secure connection is now named as such, the catalog (OPDS) screen says
  "Certificate not known. Install 'All certificates' from the store." instead
  of "could not be reached", and a refused request leaves one line in the
  device log. Checked on the X4.
- The menu language packs for Amharic, Belarusian, Central Kurdish, Kazakh,
  Kyrgyz, Macedonian, Pashto and Serbian build again; their longest help texts
  were too long for a compiled catalog and are condensed (#385).
- Book text on the Xteink readers is set in PaperPaw Sans unless you choose
  another font; bold and italic come from the family of the regular text, and
  bold text in a font without a bold face is drawn bolder.
- The update from the card's files takes its steps together and no longer
  needs minutes.
- Titles and authors of EPUB, DOCX and MOBI books are read right after the
  library looked for books, and the device rests between the steps.

- **Wi-Fi lists are quicker:** after a search only the rows that changed (a
  signal that moved, a network that is kept now) are drawn and refreshed, not
  the whole list.
- **Large scripts** (Korean, Chinese, Japanese) read their letters from the card
  with fewer reads and less memory churn.
- **The store's plugin page says what the plugin does:** its description is
  shown under the short line, and *How it works* opens the whole text.

## Known limits against Beta 3

Measured on one X4 with the same card, books and settings, Beta 4 as the release
image (flash read at 80 MHz, build of Nov 20) and Beta 3 as released (flash read at 40 MHz):

- **The X4 starts faster than Beta 3 with the release image:** 4.8 s into the last
  book against 5.4 s on Beta 3. The speed comes from the faster flash; the same Beta 4
  code at 40 MHz takes 6.6 s, so the code itself is not faster than Beta 3's.
- **The reader leaves less memory free:** after the start in the last book,
  119 KB of the heap are in use against 70 KB on Beta 3; on Home 106 to 107 KB
  against 81 KB. The difference is the native plugin host (22 KB), the
  reader and its layout (14 KB), hyphenation (9 KB) and many smaller parts.
- **Page turn and focus step are a little slower:** 0.81 s against 0.75 s for a
  page turn, 1.16 s against 0.87 s for a focus step on Home. Back from a book
  to Home is faster than on Beta 3 (0.87 s).
- The firmware image is about 5 % larger than Beta 3's.

## Changed since Beta 3

  the firmware); see "Before you update".

  can be on them.

  reading font.

  interface and its minor. The Linux emulator and tools are built for glibc
  2.35 and start on Debian 12 and Ubuntu 22.04.
- Known gap: there is no template yet for community plugins with code on
  interface 7 in the author release workflow.
